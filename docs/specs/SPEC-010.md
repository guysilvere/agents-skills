# [SPEC-010] Génération des 9 agents depuis 3 sources canoniques & CI validation/evals

> **Statut** : DONE
> **Phase Roadmap** : Phase 10 — Industrialisation « Agents-as-Code »
> **Agent(s)** : `lead-dev` → `ops-quality`
> **Dépend de** : `SPEC-001` à `SPEC-009`

---

## 1. Intent
**Problème** : Maintenir 9 fichiers agents à la main (`3 rôles × 3 outils`) garantit des dérives silencieuses à chaque mise à jour de règle (ex : règle GitHub Issues oubliée sur Claude, compteurs faux, frontmatters divergents). De plus, aucune CI n'empêche aujourd'hui le merge d'un frontmatter YAML cassé (` : `), d'une skill monolithique (> 250 lignes), d'un secret ou d'une régression de déclenchement.
**Objectif** : Passer à une **source canonique unique** (3 corps d'agents + 3 petits manifests de frontmatter par outil compilés automatiquement) et ajouter une **CI GitHub Actions** qui valide le dépôt + exécute une batterie d'evals structurels à chaque PR.

## 2. User Story
En tant que **mainteneur de `agents-skills`**, je veux **éditer un agent en un seul endroit et recevoir un feu vert automatique en PR sur la validité YAML, la parité multi-outils et les seuils tokens**, afin de **faire évoluer mon écosystème IA sans jamais introduire de régression**.

## 3. Exigences

| ID | Exigence | Critère de fin (DoD) |
|----|----------|-----------------------|
| REQ-01 | Créer `agents-src/{lead-dev,ops-quality,integrations}.body.md` + `agents-src/frontmatter/{opencode,antigravity,claude}/*.yaml` et un générateur déterministe `scripts/build-agents.mjs` générant `opencode/agents/`, `antigravity/agents/` et `claude/agents/` | [x] `node scripts/build-agents.mjs --check` vérifie que les 9 fichiers générés sont 100 % synchronisés |
| REQ-02 | Créer un script de validation `scripts/validate-setup.mjs` contrôlant : (a) YAML valide sur 100 % des skills/agents/workflows, (b) zéro ` : ` non échappé et zéro `< >` dans `description`, (c) `name == dossier` et `description.length <= 500`, (d) `SKILL.md <= 200 lignes`, (e) parité `opencode/commands/` ↔ `antigravity/workflows/`, (f) `build-agents.mjs --check`, (g) zéro terme banni (`GeniusPay`, secrets) | [x] Script autonome (Node pur, zéro dépendance lourde), exit 0 si vert, exit 1 avec rapport tabulaire si erreur |
| REQ-03 | Ajouter un fichier déclaratif `evals/skill-triggers.json` (15–20 prompts de test couvrant les 16 skills, dont les 5 skills design) + runner optionnel `scripts/eval-triggers.mjs` | [x] Jeu d'evals versionné et documenté (exécution manuelle ou CI dédiée) |
| REQ-04 | Ajouter `.github/workflows/validate-setup.yml` exécuté sur chaque PR vers `main` et push sur `testing` : lance `validate-setup.mjs`, tests des hooks (`SPEC-009`) et `gitleaks` | [x] Workflow GitHub Actions vert sur une PR de test |
| REQ-05 | Brancher `scripts/build-agents.mjs --check` en pré-vol dans `scripts/sync-skills.sh` | [x] Impossible de synchroniser des agents désynchronisés |

**Critères d'acceptation (Étant donné / Quand / Alors)**
- **REQ-01**
  - **Étant donné** une modification d'une règle dans `agents-src/lead-dev.body.md`
  - **Quand** j'exécute `node scripts/build-agents.mjs`
  - **Alors** les 3 fichiers `opencode/agents/lead-dev.md`, `antigravity/agents/lead-dev.md` et `claude/agents/lead-dev.md` sont régénérés avec chacun son frontmatter spécifique et le même corps canonique
- **REQ-02 / REQ-04**
  - **Étant donné** une PR qui introduit un ` : ` cassant le YAML dans un `SKILL.md` ou une skill de 350 lignes
  - **Quand** la CI GitHub Actions s'exécute
  - **Alors** le check échoue avec le chemin exact du fichier et la règle violée, bloquant le merge vers `main`

**Edge cases**
- **EDGE-01** : Section spécifique à un seul outil dans le corps d'un agent (ex : syntaxe `export-mcp-tokens.sh` propre à Claude) → support de blocs conditionnels simples dans `build-agents.mjs` (`<!-- only:claude --> ... <!-- /only -->`) ou section append par outil.
- **EDGE-02** : Quelqu'un édite manuellement un fichier généré `opencode/agents/lead-dev.md` → en-tête commentaire `<!-- GENERATED BY scripts/build-agents.mjs — EDIT agents-src/ -->` + échec immédiat de `--check` en CI.

**PWA / Offline** : Non applicable.
